| 项 | 要求 |

```bash
cd ~/智慧建模
```

`libs/` 目录内已随包附带 `openpyxl`，即使离线也能运行；管线会自动把 `libs` 加入搜索路径。

## 3. 一键运行

```bash
# 全流程（整理 → 实体 → 指标 → 筛查 → 图谱 → 报告；Excel 单独跑，耗时较长）
python3 app/pipeline.py tidy entities screen graph report

python3 app/pipeline.py features

# 调整口径（夜间阈值、建图金额下限、报告对象数、Excel 单主体行数）
```

运行日志实时追加到 `output/05_日志/run.log`。

不一致直接抛错（防止工作簿同名覆盖导致静默丢行）。实测输出：
`整理表_微信流水: 308 个工作簿, 合计 2928834 行 (库中 2928834)`。

## 3b. 配置平台大模型（可选，用于对话查询）

对话查询支持两种引擎，**不配密钥也能完整交付**：

| 引擎 | 说明 |
|---|---|
| 大模型 + 工具（默认） | 调用平台 `/chat/completions` 接口（兼容主流大模型服务）；模型只能通过工具查本地 SQLite，回答里的金额/笔数/行号均来自查询结果 |
| 确定性规则 | `intel/chat.py` 的纯规则问答，离线可复现、可审计；未配置或接口异常时自动回退 |

配置方式二选一：

```bash
# 方式一：环境变量（推荐，不落盘）
export SCNET_LLM_API_KEY=sk-xxxx
export SCNET_LLM_BASE_URL=https://api.educg.net/v1
export SCNET_LLM_MODEL=deepseek-v4-flash

# 方式二：本地配置文件 app/llm_config.local.json
{"base_url":"https://api.educg.net/v1","api_key":"sk-xxxx","model":"deepseek-v4-flash"}
```

> 🔒 **安全红线**：`app/llm_config.local.json` 已写入 `.gitignore`，
> **打包提交前必须确认它不在压缩包里**——密钥泄露等于把账号交出去。
> 代码里不硬编码密钥，日志与接口只回显掩码（`sk-A***…E3iE`）。

可用工具（模型自主决定调用，全部只读且强制行数上限）：
`dataset_stats`、`list_subjects`、`subject_detail`、`search_transactions`、
`relation`、`counterparties`、`graph_neighbors`、`quality_issues`、`rescreen`、`metrics_glossary`。
每次问答会在对话区显示**引擎名与工具调用链**（例如 `counterparties(5条) → search_transactions(3条)`），便于审计。

接口限流（实测遇到过 HTTP 429）已做指数退避重试（2/4/8/16 秒）；
重试仍失败时，若已取到数据会先做一次"不开工具"的总结，最后才回退规则问答。

## 4. 启动研判工作台

```bash
python3 app/server.py --port 8000
```

浏览器打开 <http://127.0.0.1:8000>。六个页签：

1. **数据治理** — 质量清单（异常/缺失/重复/解析失败）与逐文件转换记录（编码、表头列数、记录数、重复行、时间跨度）。
2. **线索筛查** — 重点对象排序表；上方可改**阈值与权重**后点“按此条件重新排序”，结果即时重算并回写数据库。点击任一行展开该对象的触发指标、其它可行解释（反证）、以及可定位到 `来源文件:原始行号` 的大额交易。
3. **关系图谱** — 资金关系有向图（方向 = 付款方 → 收款方），可按“前 N 个重点对象”“最小边金额”过滤；点节点看依据。
4. **研判报告** — 内嵌自动生成的报告，可一键重生成。
5. **对话查询** — 自然语言问法（规则解析，可离线审计）：
   - `为什么 *某某 排在前面`
   - `提现率高于 0.8 的有哪些`
   - `把夜间阈值改成 0.4 重新排序`
   - `*某某 最大的一笔交易是哪笔`
   - `*某某 和 *某某 之间有什么资金关系`
   - `哪些文件是重复的` / `数据范围`
6. **导入与处理** — 在界面里完成新数据的整条分析链路：
   - **导入数据**：拖拽或“选择文件 / 选择文件夹”上传 TXT（资金流水）与 XLSX（话单/寄递/台账/实人绑定），保留目录层级；文件落在 `data/导入数据/`，原始取证目录只读不受影响。
   - **开始处理**：选择模式后点按钮，后台依次跑 整理 → 实体 → 指标 → 筛查 → 图谱 → 报告（可勾选附带整理表 Excel 导出）。
     - 合并分析：原始取证 + 导入数据一起分析；
     - 仅分析导入数据：只分析本次导入的内容。
   - **实时进度**：六个阶段的状态、耗时、进度条与滚动日志实时显示；完成后面板给出结果摘要与“刷新查看结果”。
   - 说明：处理会重建分析库并覆盖 `output/` 对应产物；处理期间其它页签的查询会暂时不可用，完成后刷新即可。

> 平台可以**在没有任何分析结果时先启动**（页面会提示"未使用"），数据由第 6 个页签导入后跑出来。

## 4b. 关系图谱怎么看（四种格式，按需选）

| 文件 | 用途 | 规模 |
|---|---|---|
| **`资金关系图_核心网.gexf`** | **Gephi 首选**。GEXF 是 Gephi 原生格式，节点带 `viz:position/color/size`、边带 `thickness`，打开即有分层布局与配色，**不产生任何导入警告** | 235 节点 / 887 边 |
| `资金关系图.gexf` | Gephi 全量图（先看核心网，需要展开再用这份） | 2,370 / 6,683 |
| `资金关系图谱_核心网.html` | 浏览器直接打开，可缩放平移过滤，**默认首屏 97 节点 / 108 边** | 0.23 MB |
| `资金关系图谱.html` | 同上，全量数据 + 过滤器逐步展开 | 1.57 MB |
| `图谱节点表.csv` / `图谱边表.csv` | 给 Gephi/Python/Excel 通用；含两套布局坐标与逐边溯源样本 | 235 / 887 |
| `关系图谱明细.xlsx` | 人读：节点、资金边、通话边、寄递边、群体划分、关键节点、对手方角色 | 7 张表 |

**为什么 GraphML 不再作为 Gephi 首选**：实测该版本 Gephi 对 `attr.type="complex"`
（`viz:position/color/size` 的载体）报 `"complex"的属性类型不被辨识，该属性被忽略` SEVERE，
坐标与颜色会被整属性丢弃，打开就是一团黑色毛线球。现在：

- **GEXF** 承载真正的可视化属性（位置/颜色/大小/边粗细），Gephi 原生支持；
- **GraphML** 只用标量属性类型（`string/double/long`，出现 0 次 `complex`），
  并以 Gephi 会特殊识别的 `attr.name="color"` / `"size"` 命名，`x/y` 作为普通列保留 —— 作为通用交换格式，不再承诺布局还原。

**Gephi 操作**：`文件 → 打开` 选 `.gexf`；导入报告应为**无问题**；在"概览"点
**缩放适配**即可看到按角色分层的布局（上=来源端，下=末端）。属性面板已带
`角色判定 / 分档 / 综合分 / 社群 / 关联金额合计 / 关系边数 / 身份核实`，
可直接用于按角色着色、按社群分区、按金额过滤（Edges Filters → weight）。

**Gephi 里怎么让节点显示名字**（这是 Gephi 的显示开关，不是文件缺数据）：
GEXF 内 235 个节点全部带 `label`，但 Gephi 默认不绘制标签。在"概览"面板图区下方的工具栏里
点 **`A`** 图标（Draw Node Labels / 绘制标签）即可；若字太小，
`工具 → 选项 → 预览 → 字体大小` 或用 `实验室(Laboratory)` 视图核对 label 列。
标签会随节点大小自动缩放，235 个节点建议先开标签再用 `窗口 → 排序/过滤` 只看高档对象。

**静态图（无需 Gephi，文字已画在图上）**：`资金关系图_核心网.png` / `.svg`
（SVG 可无限放大、可在浏览器里悬停看完整账号与金额）。

**HTML 操作**：
- **拖动节点改位置**：按住任意节点拖动，与之相连的边会实时跟随；
  位移小于 4 像素视为单击（弹出依据面板），不会误触发拖动。触屏同样支持。
- **重置布局**：点工具栏"重置布局"清除手动拖动过的位置，恢复自动分层；
  两套布局的拖动记录相互独立。
- 滚轮**以光标为中心**缩放；在空白处拖拽平移画布；单击节点看依据与反证；
  双击节点进入"只看它的关系圈"，双击空白复位；顶部切换**流向分层**（自上而下：组织者 → 归集端 → 1级 → 2级 → 中间待定 → 未归并对手方）
/**社群聚类**布局；按最小边金额、边数上限、最小度数、"只看已归并身份证主体"过滤；
已归并主体默认显示姓名，对手方账号在放大 2 倍、双击进入关系圈或勾选"常显对手方标签"后才显示
（否则全量 2,370 节点会糊成一片）；
搜索框输入姓名/账号/身份证回车即可定位并聚焦；单击节点看依据与反证。

## 5. 人工复核怎么做

研判结论分三档：**高 / 中 / 低**。每个触发指标都带 `指标=取值` 与文字说明，并且：

- **指标字典**（`02_线索筛查/重点核查对象排序.xlsx` 的“指标字典”表）给出每个指标的定义与计算式；
- **触发指标明细**表给出支撑交易的文件与原始行号；
- 反向证据在“其它可行解释”列，用于排除合法解释后再上升为嫌疑；
- 身份未归并的对象在报告与图谱中标注 **待核查**。

复核后如需修正，可在 Web 工作台调阈值重排，或直接改 `app/intel/screening.py` 的 `DEFAULT_PARAMS`。

## 7. 已知限制

- **图谱可读性**：资金图是"星型森林"（单个主体对手方可达数千个），任何一次性全画都必然糊。
  因此提供分层布局 + 默认只画已归并主体 + 多级过滤，而不是把 2,370 个节点一次堆给你。
- **单表行数**：Excel 单工作表上限 1,048,576 行，故超大账户的整理表按 50 万行分片为多张工作表。
- **对手方身份**：微信对手方多为掩码账号，无法从现有数据还原真实身份，均标为待核查；需要协查函调取账号实名信息。
- **药品来源证据**：赛题提到的“开药量大、定频开取”需要医保结算/开药明细数据支撑，本批数据仅有寄递品名可做间接推断，报告中已作为取证缺口列出。
- **性能**：`excel` 阶段需把 292.9 万行写成 308 个工作簿（约 298 MB、11 分钟），是整条流水线最慢的一步；分析内核（tidy→report）约 11 分钟。
- **超大表**：单主体最大 732,919 行，已按 50 万行自动分片为多张工作表，数据不截断。
